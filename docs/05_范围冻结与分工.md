# 前4天范围冻结与双人分工

> 版本说明：本文保留第1—4天的阶段记录。2026-10-02已增加两路公开最新气象接入；最新能力、数据边界与验收见[实时接入说明](08_实时数据接入说明.md)。CMA账户接口、官方预警、真实AI与现场试点仍未完成。

版本：0.1。技术范围已冻结；真实场地、用户需求及正式预案待访谈确认。

## 1. 核心问题假设

管理人员需要在官方气象信息、点位台账和工作清单之间来回查找，整理本场地的待核查任务。这一需求目前来自项目设计与公开事件背景，还没有经过团队真实用户访谈证明。

验证问题：工具能否减少查找和整理时间，且不增加关键事实错误？第4天先证明流程可运行，用户效果放到后续测试。

## 2. 本阶段输入与输出

输入：一条历史或模拟气象资料、一份场地资料、5—8个点位、相应任务条目。

输出：带来源、责任角色、点位与条目编号的待核验清单；完整运行快照；Markdown和JSON导出。

本阶段不输出：实时预警、积水概率、水深、精确安全路线、自动设施开闭、已经对公众发布的通知。

## 3. 技术选择与变更说明

原方案建议Python、Streamlit、SQLite。当前电脑没有Streamlit，已有Python标准库运行时，因此实现为Python HTTP服务、HTML/CSS/JavaScript界面、SQLite记录。无需依赖安装，可直接运行；使用同一数据包和模型适配模块，后续可迁移到其他框架。

AI只选择允许的点位与条目组合，服务器再使用条目原文组装卡片。这样可避免模型改写行动要求，但也限制了智能程度。第4天不主张AI性能已经超过规则；后续根据实测决定是否增加有依据的语言简化。

## 4. 双人任务

| 任务 | A：技术 | B：场景与验证 | 交接依据 |
|---|---|---|---|
| 原型 | 运行、配置、修改、记录错误 | 以使用者身份走完整流程 | 一条演练可复现 |
| 气象资料 | 核对字段、时区、延迟 | 核对场地实际适用范围 | 来源目录与原文 |
| 点位 | 导入与结构校验 | 采集真实5—8个点位并核实 | 真实台账及授权记录 |
| 预案 | 编号、匹配条件与引用校验 | 与管理者确认任务文字和角色 | 条目来源与审核记录 |
| API | 在本地配置并验证实际调用 | 确认资料可发送范围 | 成功记录或明确错误 |
| 访谈 | 参加必要的技术解释 | 联系并完成2—3次访谈 | 真实访谈记录 |
| 验收 | 展示规则/AI模式、导出和限制 | 检查资料真实性与用户理解 | 第4天联合核对表 |

## 5. 第4天验收标准

- [x] 程序能在本地启动。
- [x] 可查看并编辑气象资料。
- [x] 可导入或编辑点位与条目JSON。
- [x] 每项任务包含引用编号和来源。
- [x] 规则演练默认得到5项任务，不误选纯大风条目。
- [x] 资料时间、缺失字段、错误引用等关键情况有检查。
- [x] 导出输入快照与结果。
- [x] 演练、草稿、未知状态清楚显示。
- [ ] 真实外部模型调用成功并保留记录。
- [ ] 场地与联系人确认。
- [ ] 完成2—3次真实访谈。
- [ ] 真实点位和工作清单经管理方核对。

这组勾选表示本次可验证的状态，不代表整个前4天任务全部完成。

## 6. 接到真实资料后的替换顺序

1. B确认用途与脱敏范围，保留授权记录。
2. A复制演练JSON，替换site、points、plans，不修改原始演练样例。
3. B逐条核对来源、责任角色和适用条件。
4. A先跑规则版本，检查遗漏、误选和资料质量。
5. 满足模型资料发送条件后，再跑AI对照，记录模型名称和结果。
6. 更新执行状态文档，只有实际完成后才勾选。
