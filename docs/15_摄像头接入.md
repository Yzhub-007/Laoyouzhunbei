# 摄像头安全抓拍与积水识别接入

推荐已有摄像平台定时输出 JPEG/PNG 抓拍，由本机服务识别可见地面积水。默认只允许本机模型；校内远程模型必须另外授权且使用 HTTPS。**不支持把画面发送到公网模型，也没有跳过证书验证或开放公网的开关。**

识别结果是待人工核验的线索，不估计水深、不判定通行安全、不决定设施开闭。程序不额外保存抓拍图片；已有图片文件由摄像平台管理。应用只保留结构化观测、采集时间与图片指纹，并使用受保护存储。查看状态需登录；只有管理员可以修改监测来源。

## 1. 在本机保存模型配置

不要把密钥写入源码、网页表单、命令行参数或聊天。使用本机控制台的隐藏输入，将值保存到 Windows 当前账户保护的 `runtime/secrets.dpapi`：

```powershell
python security_cli.py set-secret VISION_ENDPOINT
python security_cli.py set-secret VISION_API_KEY
python security_cli.py set-secret VISION_MODEL
```

上述 `python` 指启动项目使用的 Python 解释器；若它没有加入 PATH，请使用该解释器的完整路径。命令会逐项提示隐藏输入，完成后重启项目。自定义数据库目录时，为命令补充 `--runtime` 并指向数据库同级目录。

- `VISION_ENDPOINT`：本机示例为 `http://127.0.0.1:8000/v1/chat/completions`。
- `VISION_API_KEY`：模型服务所需密钥；无认证的本机兼容服务也需按该服务约定填写非空值。
- `VISION_MODEL`：本机服务中实际部署、支持图片输入的模型名称。

接口采用 Chat Completions 兼容格式，接收 `messages` 中的 Base64 `image_url`，返回 `choices[0].message.content`。不会自动复用 `LLM_*`，不会在配置缺失或失败时调用其他模型。地址不能含账号密码、查询参数或片段。

旧 `.env` 在启动时会迁移到加密配置并清除其中的明文配置，后续请使用上述控制台管理。历史副本、编辑器备份以及已被外部备份的软件保留副本不会因此自动消失；已暴露的密钥应由管理员更换。

## 2. 校内 HTTPS 服务的明确授权

本机 `localhost`、回环 IPv4 地址及 `::1` 可使用 HTTP/HTTPS。其他服务必须同时符合以下条件：

1. 使用 HTTPS，证书由系统信任且匹配服务主机名。
2. 在对应用途的 `*_TRUSTED_ORIGINS` 中登记精确的 `scheme://host:port`。端口必须显式填写；不接受通配符、路径或末尾斜杠。
3. DNS 返回的**每一个地址**都属于 RFC1918 内网、IPv6 ULA 或回环范围。公网、链路本地、元数据服务、文档保留地址等均拒绝。

配置用途相互独立：

| 配置项 | 授权用途 | 示例值 |
| --- | --- | --- |
| `VISION_TRUSTED_ORIGINS` | 发送裁剪后图片的校内模型 | `https://vision.school.internal:443` |
| `CAMERA_TRUSTED_ORIGINS` | 下载校内摄像头抓拍 | `https://camera.school.internal:443` |
| `MONITOR_TRUSTED_ORIGINS` | 获取结构化监测 JSON | `https://sensor.school.internal:443` |
| `LLM_TRUSTED_ORIGINS` | 发送任务资料的校内文字模型 | `https://text-model.school.internal:443` |

例如，先运行 `python security_cli.py set-secret CAMERA_TRUSTED_ORIGINS`，再在隐藏提示中输入摄像网关的 origin。多个 origin 可用逗号分隔，也可填写 JSON 字符串数组。此授权与 `VISION_ENDPOINT` 的具体接口路径是不同配置。

实际请求会重新检查所有 DNS 地址，并连接已验证的固定 IP，同时保留原始主机名进行 TLS 验证。程序不使用系统代理、不跟随重定向。内网 CA 应通过校内既定的系统信任流程配置；不要关闭证书校验。**远端明文 HTTP 不再允许，即使地址位于内网。**

## 3. 配置抓拍来源与隐私区域

在管理员的监测配置中添加摄像头来源，例如：

```json
{
  "id": "gate-camera",
  "name": "入口地面抓拍",
  "point_id": "ZJG-P01",
  "kind": "camera",
  "transport": "vision",
  "input_type": "image_url",
  "url": "https://camera.school.internal/snapshots/gate.jpg",
  "enabled": true,
  "vision_enabled": true,
  "max_age_seconds": 300,
  "roi": [0.1, 0.45, 0.8, 0.5],
  "privacy_masks": [[0.1, 0.45, 0.2, 0.2]]
}
```

URL 必须直接返回图片，不能是登录页、网页播放器或视频流。源地址不能包含账号密码或密钥查询参数；需要摄像平台认证时，请由受控的本地或校内网关完成认证后提供符合上述规则的抓拍。模型授权与抓拍授权分别配置；授权抓拍主机并不授权它接收图片。

`roi` 和 `privacy_masks` 中的矩形均为 `[x, y, width, height]`，以 **0—1 比例**表示相对于方向校正后的完整原图的位置；必须具有正面积且不能超出图片。程序先根据 EXIF 校正方向，再按完整原图坐标填黑所有遮挡区，随后裁剪 ROI，并重编码为不携带 EXIF、文字、ICC 等元数据的 PNG。

- 本机模型可以不配置 ROI；仍建议只保留积水判断所需地面范围。
- 校内远程模型必须配置**非全图** ROI，否则在读取抓拍前停止识别。
- `privacy_masks` 可配置最多 30 个矩形；遮挡区属于裁剪前的原图坐标，不是 ROI 内坐标。
- ROI 按像素向内取整，遮挡向外取整；过小而无法形成有效像素区域的 ROI 会被拒绝。
- 这不是自动人脸或车牌识别。移动人物仍可能进入未遮挡区域，需要调整视野、遮挡区域及现场摄像安排。

安全处理依赖 Pillow；缺失时会停止识别，不会直接发送未经处理的原图。HTTP 抓拍不需要 FFmpeg。图片输入和处理后图片均限制 5 MiB，边长最多 8192 像素、总像素最多 2400 万；不接收动画图片。网关输出约 1280×720 的必要视野通常便于检查。

画面只在内存中处理，不写临时图片。本机或校内模型服务仍需由管理员关闭请求体日志、输入留存与非必要转发；应用的网络检查不能约束模型服务器收到图片后的行为。

## 4. 采集时间、断线与重复画面

网关必须返回真实采集时间。默认优先读取 `X-Captured-At`，其次读取 `Last-Modified`：

```http
Content-Type: image/jpeg
X-Captured-At: 2026-10-03T12:30:00+08:00
Cache-Control: no-store
```

也可设置 `timestamp_header: "X-Frame-Time"`。时间需为含时区的 ISO 时间或 HTTP 日期；`Last-Modified` 使用 GMT。不要把每次请求时刻当作拍摄时刻。缺少时间、时间格式无效、晚于本机或超过有效期时，不生成当前观测。

相同原始图片指纹不会重复发送给模型、重复计入独立样本或刷新观测时间。断线后返回的旧图片不能因此成为新证据。设备时间与更新逻辑仍需接入时核对，应用无法单凭图片证明时间真实性。

本地网关也可将图片原子写入数据库同级的 `monitor-input` 目录；默认是 `runtime/monitor-input`。来源改为 `"input_type": "image_file"`、`"path": "gate.jpg"` 并移除 `url`，其他授权与隐私字段保持适用。路径只能是该目录下的相对路径；文件修改时间必须保留实际采集时刻。该文件是上游输入，不是应用生成的加密图像存档，请由网关限制访问并管理留存。

## 5. RTSP 与本地录像

**当前安全版禁用 RTSP 和 RTSPS 直连。** 现有 FFmpeg 抽帧链路无法一致保证 TLS 主机名验证及 DNS 地址钉住，因此不会尝试读取。请由既有摄像平台或校内网关转换为本机/校内 HTTPS 抓拍。旧 `input_type: rtsp` 配置需要修改；不要通过关闭 TLS 校验恢复连接。

本地录像只支持开发接口 `analyze_video_replay` 的离线核验，不进入当前监测状态。录像放在 `monitor-input` 内，使用 `input_type: video_file`、相对 `path`、`offset_seconds` 和明确的 `vision_enabled`。仍遵循同样的模型边界、ROI、遮挡与元数据清理。

录像抽帧需要现有 FFmpeg：可通过安全控制台设置 `VISION_FFMPEG` 的完整本机路径，也可使用项目 `tools/ffmpeg.exe` 或 PATH 内的 FFmpeg。不自动安装。支持常见 MP4/MOV/MKV/WebM/AVI/TS，拒绝 HLS/concat 播放列表和网络协议。回放结果标记 `mode: replay`、`replay: true`，不提供可用于当前观测的 `observed_at`。文件修改时间不是录像拍摄时间。

## 6. 识别输出与验证范围

模型必须按兼容协议返回严格 JSON：

```json
{"water_detected": true, "confidence": 0.84, "quality": "good", "summary": "可见依据"}
```

自由文字 `summary` 只用于协议校验，**不会进入观测记录**。应用根据 `water_detected` 与 `quality` 生成固定描述，避免将姓名、车牌或画中文字写入结果。其他额外字段、非法数值和矛盾组合会被拒绝；`quality: poor` 一律归为未知。模型自报置信度不是场地验证后的准确率。

```powershell
python -m unittest discover -s tests -p test_camera_vision.py -v
python -m unittest discover -s tests -p test_network_policy.py -v
```

测试覆盖私有网络边界、DNS 混合结果与固定 IP 连接、TLS 主机校验、重定向与代理、ROI/遮挡、元数据清理、过期/重复画面及回放隔离。合成测试不表示真实摄像头已接通，也不证明现场识别准确率；投用前仍需用对应点位昼夜、雨前雨后与遮挡画面核验。

账号、权限、加密、留存与已知边界见[安全配置与使用边界](17_安全配置与使用边界.md)。
