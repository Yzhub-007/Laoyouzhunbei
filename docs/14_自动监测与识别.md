# 自动监测与识别 · v0.6

本版本把“看数据、填状态”改为后台采集与自动判断。默认首页为监测总览；原有资料建档、规则／AI演练、人工审核和计时试验继续保留。

## 已实现的流程

1. 完成首次管理员设置后，服务器持续更新公开天气数据和已配置的设备。关闭浏览器不会停止采集，关闭服务器会停止。
2. 公开天气数据按天气代码、降水和风速识别状态，保留城区模型与机场观测各自的来源及时间。上游气象请求仍有10分钟缓存间隔。
3. 摄像头抓拍先核对画面时间与质量，再交给用户配置的视觉服务识别可见积水。重复图片不累计为连续的新证据。
4. 已有视频分析平台可直接推送识别结果，也可让本机定时读取其 JSON 文件或 HTTP 接口。已标定的地面水深传感器是另一种可选来源。
5. 点位卡片自动更新，显示判定依据；根据保存的点位和预案自动列出待核验任务。状态变化保存为本地事件。
6. 人工校正单独记录人员、依据和有效期，同时保留原自动判断。校正不等同于关闭道路或发布通知。

识别积水、判断管理措施、发布公众提示是三个不同步骤。这里的自动任务来自现有预案，仍供管理人员核验。摄像头不能覆盖的区域保持未知。

## HTTP 定时抓拍接入

这是当前推荐的摄像头方式，无需 FFmpeg。

1. 在“试点总览”核实并保存真实点位，以便把镜头关联到具体位置。
2. 使用 `python security_cli.py set-secret KEY` 隐藏录入 `VISION_ENDPOINT`、`VISION_MODEL` 和认证配置，重启服务器。默认仅允许本机服务；校内服务须 HTTPS、精确 origin 白名单及私有 DNS 地址。公网服务被拒绝。
3. 在监测页添加摄像头，选择“HTTP 抓拍图片”，填写点位及图片地址。只有明确启用视觉识别后才会发送该源的画面。
4. 图片服务须返回真实拍摄时间，例如 `X-Captured-At` 的带时区 ISO 时间，或具有采集时间语义的 `Last-Modified`。抓取成功的时刻不等于拍摄时刻。
5. 保存后等待后台采集；在来源状态中查看连接、缺少模型、时间缺失、过期、画面质量或识别错误。

详细图片协议、ROI与隐私遮挡、视觉服务格式见[摄像头接入说明](15_摄像头接入.md)。RTSP直连已禁用。权限及保留期见[安全说明](17_安全配置与使用边界.md)。本版本没有预置摄像头账号或模型密钥，也没有用演示图片填充真实监控。

## 配置与数据位置

- `runtime/monitor-config.json`：监测配置及版本号，文件内容已加密。
- `runtime/monitor-input/`：本地网关输出 JSON 或持续更新的图片；文件路径均相对此目录，不允许越界。
- `runtime/runs.sqlite3`：加密数据库，含原有记录及 `monitor_*` 表。使用 `--db` 指定其他数据库时，监测配置和输入目录放在该数据库旁。
- `runtime/secrets.dpapi`：本机模型配置及秘密，由命令行加密保存，不通过网页返回。

没有设备时所有点位显示未知；没有视觉服务时摄像头不会被伪装成已识别。公开天气无需配置模型，但网络或上游服务不可用时保留缺测说明。

高级 JSON 配置的默认值：

```json
{
  "poll_seconds": 60,
  "depth_watch_cm": 2,
  "depth_alert_cm": 15,
  "camera_confidence": 0.8,
  "confirm_samples": 2,
  "sources": []
}
```

这些水深、连续样本和置信度值是项目可调的识别参数，不是官方预警标准或已验证的现场最优阈值。应使用本点位的真实样本校准。模型给出的置信度也不等于经过标定的正确率。

## 接入已有识别平台

在网页添加 `kind: "camera"`、`transport: "push"` 的来源，绑定保存的点位。其识别结果如下：

```json
{
  "source_id": "gate-camera",
  "observations": [{
    "observed_at": "2026-10-03T12:00:00+08:00",
    "water_detected": true,
    "confidence": 0.92,
    "quality": "good"
  }]
}
```

上面是协议示例时间，不是当前现场记录。设备必须使用真实拍摄时间。摄像头结果表达画面疑似积水，不表达水深或区域洪水等级。

本机网关须先用操作员账户向 `POST /api/auth/login` 登录，保留响应 Cookie 和 `csrf_token`。全部受保护API请求都要带 Cookie 与 `X-App-Token: <csrf_token>`；写请求还须 `Content-Type: application/json` 及与服务地址一致的 `Origin`，例如 `http://127.0.0.1:8765`。观测提交到 `POST /api/monitor/ingest`，会话过期需要重登。不存在匿名bootstrap取令牌机制。网关账户也拥有操作员其他写权限，须保存在受控本机环境。服务只监听本机，不向公网开放设备接口。

定时读取方式使用 `transport: "file"` 与 `path: "gate.json"`，或 `transport: "http"` 与 `url`。响应是单条观测对象，或者 `{"observations": [...]}`。相同来源、相同观测时间的重复内容不重复保存，矛盾内容拒绝；旧记录不覆盖较新的状态。

水深设备改用 `kind: "water_depth"`，观测使用 `depth_cm`、`depth_reference: "ground"` 和 `observed_at`。只有已校准至本点位地面的水深适用，不能直接接入河道海拔水位或未经换算的距离。

## 状态与失效处理

| 情况 | 系统行为 |
| --- | --- |
| 天气模型下雨，现场无有效设备 | 天气显示降雨，现场保持未知 |
| 新近、清晰、置信度满足要求的镜头出现水面 | 画面疑似积水，保留依据与连续观测数 |
| 水深持续达到配置阈值 | 显示相应水深状态，引用设备观测 |
| 模糊、遮挡、低置信度、断线、过期 | 不作为当前肯定判断依据 |
| 多个设备结果不一致 | 显示冲突，保留异常证据供复核 |
| 人工校正到期 | 恢复按当前有效证据自动判断 |
| 新异常与“未检出积水”校正矛盾 | 保留自动异常，不让旧校正掩盖新异常 |

气象代码与变量语义参考 [Open-Meteo 官方文档](https://open-meteo.com/en/docs)。公开模型位置仍为杭州城区参考网格；机场观测仍为萧山机场。两者都不能直接说明紫金港具体入口是否积水。

## 验证

运行 `python -m unittest discover -s tests -v` 验证解析、失效、去重、规则、持久化和 HTTP 接口。浏览器测试 `tests/browser_monitor.cjs` 使用隔离数据库和合成数据。

合成测试只证明代码按协议处理数据，不能证明视觉模型在现场的识别准确率。真实验收需使用接入的摄像头验证白天／夜间、反光、湿地面、积水、遮挡、雨滴和断线场景，并由现场人员标注对照。
