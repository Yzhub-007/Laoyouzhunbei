# v0.8 安装与交付

这是可独立安装的完整源码包，包含应用、页面、合成演练模板、测试和操作文档。它不包含 Python 安装程序、已训练模型、商业算法授权或真实监控数据。摄像头与识别模型仍需要在使用单位配置并进行现场验收。

## 1. Windows 安装

需要 Windows、Python 3.11 或更新版本（包含标准库 SQLite 的 `serialize/deserialize`）、Pillow 12.3.0。建议使用 Python 3.12 的 64 位 Windows 标准安装。Pillow 是唯一第三方运行依赖；不需要安装训练框架。

1. 把 ZIP 完整解压到自己的本地目录。不要直接在压缩包中启动，不要放在共享可写目录。
2. 使用今后持续运行项目的**日常 Windows 账户**打开 PowerShell。不要由临时沙箱账户初始化正式数据。
3. 进入解压目录，执行：

```powershell
Set-Location -LiteralPath 'D:\项目\Laoyouzhunbei-v0.8'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
```

上面的路径需要换为实际路径。`ExecutionPolicy Bypass` 只作用于这个 PowerShell 进程，不修改系统执行策略。单位设备受到组策略限制时，由本机管理员按单位规定处理。

`setup.ps1` 会创建本目录 `.venv`，从 PyPI 安装 `requirements.txt` 锁定的 Pillow，最后做离线自检。它不会安装模型、读取监控或创建管理员账户。Python 没有加入 PATH 时可以指定解释器：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -PythonPath 'C:\Python312\python.exe'
```

Python 可从 [Python 官方 Windows 下载页面](https://www.python.org/downloads/windows/) 安装。锁定的 Pillow 版本和 Windows 支持说明见 [Pillow 安装文档](https://pillow.readthedocs.io/en/stable/installation/index.html)。

## 2. 启动与首次管理员

双击 `start.cmd`，或在 PowerShell 运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

启动器优先使用本目录 `.venv`，其次使用指定的 `-PythonPath`、可用的 `py/python`；现有开发机器最后才尝试 Codex 随附 Python。换电脑部署不依赖 Codex。启动前会检查版本、SQLite、Pillow、目录写权限和端口，并拒绝用 `CodexSandbox*` 账户启动正式实例。

访问 <http://127.0.0.1:8765/>，然后在同一 Windows 账户的 PowerShell 中读取初始化码：

```powershell
Get-Content -LiteralPath .\runtime\setup-code.txt
```

将码输入页面并创建管理员；密码至少 15 个字符。码有效 20 分钟，仅能初始化一次，不要发送到聊天或共享渠道。码过期但尚未创建管理员时，可重新生成：

```powershell
& .\.venv\Scripts\python.exe -X utf8 .\security_cli.py setup-code
Get-Content -LiteralPath .\runtime\setup-code.txt
```

已有管理员后不能再次初始化；上述命令不是密码重置工具。浏览器中的管理员、操作员、观察员是应用角色，不改变 Windows 文件权限。

正常停机在服务窗口按 `Ctrl+C`。端口冲突时先确认是否已有实例；也可以指定另一个端口：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -Port 8768
```

v0.8 对同一数据目录持有服务实例锁：即使使用不同端口，也会阻止重复启动。请先停止旧实例再启动新版本；锁由进程退出自动释放，不要手工删除正在使用的锁文件。不同数据目录可用于隔离测试。服务仅供本机访问，不能把本地 HTTP 端口直接暴露到公网。

## 3. 自检与配置

独立自检不读取 `runtime`、不解密数据库、不外连、不访问摄像头。它只短暂绑定本机端口后立即释放，并在项目目录创建后删除一个空探测文件。

```powershell
& .\.venv\Scripts\python.exe -X utf8 .\doctor.py
& .\.venv\Scripts\python.exe -X utf8 .\doctor.py --json --skip-port
```

服务器已经运行时，自检默认会报告端口被占用，这是预期结果；使用 `--skip-port` 只检查依赖。`--check-startup` 会将临时沙箱账户视为错误，普通诊断会提示警告。

API 地址、模型名、密钥和允许的内网服务地址通过隐藏输入写入加密配置：

```powershell
& .\.venv\Scripts\python.exe -X utf8 .\security_cli.py set-secret VISION_ENDPOINT
& .\.venv\Scripts\python.exe -X utf8 .\security_cli.py set-secret VISION_API_KEY
& .\.venv\Scripts\python.exe -X utf8 .\security_cli.py set-secret VISION_MODEL
```

命令执行后按提示输入值，输入内容不会回显。不要把秘密写入命令参数或 `.env.example`。配置修改后重启服务生效。更多字段见 `.env.example` 和 [安全配置与使用边界](17_安全配置与使用边界.md)。

视觉 API 默认只允许本机服务；校内服务需配置精确 HTTPS 来源白名单并使用可信证书，公网模型端点会被拒绝。相机侧使用 HTTPS 抓拍网关或本机图像输入，RTSP 网络直连当前禁用。非本机视觉服务还要求明确设置非全画面的识别区域，隐私遮挡应由管理人员检查。

天气接入可能访问预先配置的公开天气服务，这与发送相机画面的模型通路分开。离线环境没有实时天气时会显示不可用或过期状态，不会将其伪装成实时观测。模型未配置时，演练规则和手工核验流程仍可用。

## 4. 离线依赖安装

在另一台联网、具有相同 Windows 架构和目标 Python 版本的机器准备 wheel：

```powershell
py -3 -m pip download --only-binary=:all: --dest .\wheels --index-url https://pypi.org/simple -r .\requirements.txt
```

把源码包、`wheels` 目录和适用的 Python 官方安装程序转移到目标机器，安装 Python 后运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -OfflineWheelDirectory 'D:\依赖\wheels'
```

此模式使用 `--no-index`，不会访问 PyPI。wheel 必须匹配目标 Python 与系统架构。模型文件和推理服务应由单位另行准备，项目安装器不会下载它们。

## 5. 数据保留、备份与升级

`runtime` 中的账户、配置和数据库由 Windows DPAPI 加密，绑定初始化它们的 Windows 账户及相应系统凭据。把这些文件复制到另一台电脑或另一个账户，通常不能直接解密；不能把“有 ZIP 副本”当成已验证的灾难恢复方案。详情见 [Microsoft DPAPI 文档](https://learn.microsoft.com/en-us/windows/win32/seccrypto/data-protection)。

本交付包是**干净源码包**，不带现有账户、设置码、密钥、真实点位记录、处置记录或截图。使用它创建的是新实例。要更新现有实例，请先在原 Windows 账户下正常停机、备份其 `runtime` 和源码，并由该账户验证恢复方式；再覆盖发布文件，保留原 `runtime`。不要用干净安装覆盖或删除业务数据。

加密迁移备份不会自动删除；需要管理员核实恢复能力后按单位规定管理。加密不保证同一系统账户被攻破后的安全，也不等于清除以前磁盘中的明文残留。历史数据的跨账户迁移不包含在本公共包中。

## 6. 发布包校验与重新构建

ZIP 内含 `RELEASE_MANIFEST.json`，逐项记录发布文件大小和 SHA-256（清单自身除外）；ZIP 旁的 `.zip.sha256` 是整个压缩包的校验值。它们用于检查传输完整性，不是第三方签名或安全认证。

```powershell
Get-FileHash -LiteralPath '.\涝有准备_完整项目_v0.8.zip' -Algorithm SHA256
```

在源码目录生成新的干净包：

```powershell
& .\.venv\Scripts\python.exe -X utf8 .\build_release.py --output 'D:\交付\涝有准备_完整项目_v0.8.zip'
```

打包器仅收集根目录应用源码、部署入口、`web/docs/tests` 中允许的源码格式，以及明确列出的合成数据模板。它不扫描或读取 `runtime` 和 `evidence`，排除 `tools`、`.env`、缓存、虚拟环境和旧压缩包，并拒绝可将目录引向别处的符号链接及 junction。任何个人采集资料都应保存在 `runtime` 内，不要混入可发布源码或模板目录。

## 7. 验证范围

后端回归测试：

```powershell
& .\.venv\Scripts\python.exe -X utf8 -m unittest discover -s .\tests -p 'test_*.py' -v
```

测试使用隔离临时目录，不需要真实摄像头或生产账户。浏览器测试另需 Node.js、Playwright 和浏览器，不属于运行依赖；按测试文件的参数针对隔离测试实例执行。安装完成、自检通过、代码测试通过，都不能替代真实点位的积水识别验收与管理方对正式预案的审批。
