# v0.3 行动闭环与 Agent 优化

日期：2026-10-02。依据《两周冲刺实施方案》第3节与第5—6天技术目标，在既有Python标准库服务上继续实现。

## 已实现

- 六个工作视图：最新气象、气象资料、点位与条目、行动清单、公众提示、运行记录。
- 任务概览、关键词搜索与状态筛选；桌面双列卡片和窄屏单列展示。
- 人工修改任务及角色；记录操作人、核验依据、现场状态与时间。
- 状态流转：待核验→已确认→处理中→已完成；支持排除与退回待核验。禁止跳过确认直接完成。
- 已确认内容修改必须退回待核验。原始任务、修改前后值保留在运行记录中。
- 公众提示只从已确认任务及人工确认的关闭/限制使用状态生成。未知状态不能生成通行结论。任务更新使对应旧提示失效。
- 公众提示固定带“演练草稿”、确认依据、来源与时间；本机下载，不包含外部发布接口。
- 反馈记录已接收、需要解释或已处理，保留反馈人角色及说明。
- 最近50次运行可恢复输入快照、审核状态和反馈。旧版记录读取时兼容补充初始工作流字段，不重写原始输入。
- SQLite事务与版本号检查防止旧浏览器覆盖更新；新接口沿用本机Host、Origin和请求令牌校验。

## Agent职责

匹配过程分为输入校验、建立候选、选择条目、引用校验、交给人工五阶段。此处展示的是程序执行摘要，不是模型内部推理。

规则模式不调用AI。AI模式仍只从允许的点位/条目组合中选择，任务与角色使用原始资料。新增未选候选列表和没有候选的点位提醒，便于发现可能遗漏；不会把规则候选数量解释成真实风险数量。

成功调用且通过结构与引用校验后，记录模型名称、原始匹配JSON和服务商返回的usage（如有）。运行记录不包含服务密钥。失败调用仍直接报错，不静默切换规则结果；本版尚未建立失败模型响应归档和正式对照评估工具。

## 验证

- 后端：44项unittest通过，包含原有34项规则与气象测试、新增审核流转、草稿失效、反馈、AI遗漏记录、HTTP持久化、陈旧版本写入拒绝及端口独占检查。
- 浏览器：Edge headless 16项检查通过；覆盖完整审核→提示→反馈→刷新恢复→退回失效流程、搜索筛选、390px任务/提示/气象页面无横向溢出及无脚本错误。
- 浏览器自动化将气象接口设置为明确的测试故障，验证降级展示；不把本轮检查称为实际联网气象验收。
- 截图与机器可读检查结果：`evidence/v03/`。测试数据库使用`runtime/qa-v03.sqlite3`，独立于用户的`runtime/runs.sqlite3`。
- 未进行手机真机、真实管理人员使用测试或真实外部模型调用。没有AI优于模板的效果结论。

运行测试：

```text
python -m unittest discover -s tests -v
python server.py --port 8766 --db runtime/qa-v03.sqlite3
```

另开终端执行`node tests/browser_workflow.cjs`。浏览器测试需要Playwright和Edge；`PLAYWRIGHT_MODULE`可指向已安装的Playwright模块，`TEST_URL`可指定测试服务器。
