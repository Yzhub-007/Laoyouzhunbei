# 积水识别现场验收工具

本工具回答“这批独立现场样本中，模型漏掉了多少积水、产生多少误报，以及看不清时是否拒绝判断”。它只读取人工标注和已有预测结果的 JSON，**不连接摄像头、不调用模型、不训练模型，也不读取或保存图片**。

随项目提供的 `data/evaluation/vision_acceptance_example.json` 是完全合成的教学数据。其数值不是实测结果，不代表任何模型准确率；无论阈值如何设置，合成数据都不能得到现场验收通过状态。

## 1. 先准备独立的现场样本

由获得授权的人员采集并保管点位样本，先限定需要观察的地面区域、遮挡无关的人脸或车牌，并按本单位要求控制访问、留存和删除。当前行动助手不自动保存摄像头抓拍原图；本工具不会改变这一设置。

样本应覆盖真实积水、普通干地面、湿地、倒影、水池、夜间、灯光反射、镜头雨滴和遮挡等实际情况。数量与阈值需要结合点位风险和管理方要求确定，不能用“达到固定张数”代替代表性验证。

先按降雨过程、独立采集时段或其他有明确间隔的场景事件划分 `event_id`，再分配 `train`、`validation`、`test`。同一次连续拍摄的相邻图片属于同一事件；不要逐帧随机分组。同一场降雨同时涉及多个点位时，可以用相同事件编号，避免把相关画面包装成独立事件。

- `train` 可用于训练或微调。
- `validation` 可用于选择模型、置信度阈值和告警策略。
- `test` 是最终独立测试；冻结模型与策略后才用于验收。看到测试结果后改了策略，应准备新的独立测试数据。

人工标注人员应按照事先统一的定义判定场景，避免直接复制模型答案。出现争议时复核；无法从画面判断时使用 `unusable`，不要强行标为无积水。

工具会拒绝重复帧编号，以及同一事件出现在不同 split 的数据。**它无法仅凭编号识别图片改名、相邻画面或人为拆开的同一事件**，因此还要求采集负责人用 `independent_events_confirmed` 明确声明是否已核实独立性。

## 2. 输入格式

文件采用 UTF-8 JSON，最多 4 MiB、20000 条记录。完整结构见合成样例。

```json
{
  "schema_version": 1,
  "dataset_kind": "field",
  "independent_events_confirmed": true,
  "records": [
    {
      "point_id": "P001",
      "event_id": "E001",
      "frame_id": "F001",
      "split": "test",
      "label": "water",
      "prediction": "unknown",
      "confidence": 0.51
    }
  ]
}
```

以上单条记录只演示格式，样本不足，不能验收通过。

| 字段 | 规则 |
|---|---|
| `schema_version` | 整数 `1`，不接受布尔值 |
| `dataset_kind` | 真实授权现场数据填 `field`；模拟、构造或合成数据填 `synthetic` |
| `independent_events_confirmed` | 严格布尔值，未核实独立采集事件时填 `false` |
| `point_id` / `event_id` / `frame_id` | 使用匿名编号；1–64 个 ASCII 英数字、下划线、点或短横线，首字符为英数字；帧编号必须全局唯一 |
| `split` | `train`、`validation` 或 `test`；同一事件不可跨 split |
| `label` | 人工真值：`water` 有积水、`clear` 无积水、`unusable` 画面不足以确定真值 |
| `prediction` | 模型判定：`water`、`clear` 或 `unknown`；接入程序应把看不清、拒绝判断或失败映射为 `unknown` |
| `confidence` | 可选的模型自报置信度，0–1 有限数值；不是准确率，也不参与本工具验收判断 |

所有记录均需提供人工标注和预测，避免悄悄丢弃失败调用或困难样本。额外元数据和自由文字不会复制进报告，不要因此把个人信息或密钥放入输入文件。报告按测试集首次出现顺序使用 `point_001`、`event_001` 等匿名引用；原始编号映射由数据负责人保留。

## 3. 运行统计

在项目目录中使用 Python 3.11 或更新版本运行。工具只使用 Python 标准库。以下以本机已安装的 `python` 命令为例；也可以换成用于启动项目的 Python 完整路径。

```powershell
python -X utf8 .\vision_acceptance.py `
  --input .\data\evaluation\vision_acceptance_example.json `
  --output .\vision-example-report.json
```

未配置阈值时，生成统计报告，状态为 `not_evaluated`，退出码为 `1`。这表示尚未验收通过，不表示文件读取失败。示例数据始终只能用于演示。

输出目录必须已经存在，报告文件名必须尚未使用。工具不会覆盖旧报告，避免删除失败记录；每次运行应选择新文件名。

## 4. 按管理方确认的阈值验收

先由管理方结合处置风险确认阈值，再在一个独立 JSON 文件中完整填写以下 9 个字段。项目不预设官方阈值，不根据测试结果自动放宽要求。

| 阈值字段 | 数值要求 | 作用 |
|---|---|---|
| `min_water_recall` | 0–1 | 水样本检出率最低要求 |
| `min_water_precision` | 0–1 | 在有明确真值的水告警中，真正有水的比例最低要求 |
| `max_clear_false_positive_rate` | 0–1 | 无水样本误报率上限 |
| `max_usable_unknown_rate` | 0–1 | 在有明确真值样本中的无法判定率上限 |
| `max_unusable_definite_rate` | 0–1 | 人工认为看不清时，模型仍肯定判断有水或无水的比例上限 |
| `min_test_events` | 整数，至少 2 | 独立测试事件最低数量 |
| `min_water_samples` | 正整数 | 有水样本最低数量 |
| `min_clear_samples` | 正整数 | 无水样本最低数量 |
| `min_unusable_samples` | 正整数 | 质量不足样本最低数量 |

计数阈值最多 20000；比例不接受字符串、布尔值、NaN 或 Infinity。完整填写后运行：

```powershell
python -X utf8 .\vision_acceptance.py `
  --input .\field-results.json `
  --thresholds .\approved-thresholds.json `
  --output .\field-acceptance-report-001.json
```

同一套阈值同时用于总体和每个点位，防止大量容易样本掩盖少量困难点位。事件明细用于检查相关性和失败分布，不要求单个事件同时具有全部类别。

`min_test_events >= 2` 只是工具阻止单事件冒充独立验证的最低约束，**不表示两个事件足以证明可靠**。应按实际点位、季节、昼夜条件和需要的统计把握度增加事件与样本。

## 5. 如何读报告

报告仅对 `test` 集计算指标，同时保留各 split 的数量、按点位统计及按事件统计。

| 指标 | 含义 |
|---|---|
| `water_detection_recall` | 正确检出的有水样本 ÷ 全部人工标为有水的样本 |
| `water_precision` | 正确水判定 ÷ 有明确真值样本中的全部水判定；`unusable` 无法确认水体真值，另行检查 |
| `false_positive_count` / `clear_false_positive_rate` | 无水却判有水的数量及占无水样本的比例 |
| `explicit_water_misses` | 有水却明确判为无水的数量 |
| `unknown_water_undetected` | 有水却无法判定的数量 |
| `total_water_undetected` | 上述两种未检出之和；unknown 不会从检出率分母消失 |
| `unknown_rate` | 全部测试样本中的无法判定率，包括低质量样本 |
| `usable_unknown_rate` | 人工已能确定有水或无水，但模型无法判定的比例 |
| `unusable_definite_count` / `unusable_definite_rate` | 画面不足以确定真值时，模型仍肯定判为有水或无水的数量及比例 |
| `water_event_detection_recall` | 有水事件中至少一张真正有水图片被检出的事件比例 |
| `false_alarm_event_count` | 至少包含一次无水误报的事件数量 |

例如 10 张有水图片中，6 张检出、2 张误判无水、2 张无法判断，检出率是 `6 / 10 = 0.6`，不是 `6 / 8`。置信度即使接近 1，也不能改变这些统计。

同一事件包含 1000 张相邻帧仍只计为 1 个事件。“事件被检出”不代表检出及时、整个事件持续正确、准确估出水深或确认疏散安全。本工具没有时间序列、告警合并和真实值守时长数据，**不计算每日告警负担、首次检出延迟或漏报持续时长**；这些需在实际并行试用中另行记录。

分母为零时，指标输出 JSON `null`，不会伪装成 0 或 100%。

| `status` | 含义 | CLI 退出码 |
|---|---|---|
| `not_evaluated` | 未提供完整阈值，或数据为合成示例；只统计 | 1 |
| `insufficient` | 独立性未确认、数量不足、指标没有分母，或某点位资料不足 | 1 |
| `failed` | 在可评估的数据中，未达到已配置要求 | 1 |
| `passed_configured_thresholds` | 这批真实测试数据的总体与每个点位均达到自定要求 | 0 |
| 无报告、数据校验错误 | 发生泄露、字段错误、重复 JSON 字段、文件超限或无法创建新报告等 | 2 |

`passed_configured_thresholds` 不是正式安全认证，也不能外推到未测试摄像头、季节或其他现场。上线前仍需管理方审核；模型、镜头位置、ROI、照明或策略变化后，应重新验证。

## 6. 与当前行动助手的关系

已有摄像头和 `VISION_*` 接入负责产生识别结果；本工具是独立的现场验收环节，不会因为运行一次验收就自动启用某个模型或更改预案。

建议保留模型版本、采集方案、阈值批准记录和报告版本，在已有监控流程旁并行试用。误报、漏报和不可判定样本经授权后交由人工复核，再决定调整区域、模型或告警策略。模型识别结果用于形成待核验任务，正式预案与处置授权仍沿用单位审核流程。
