四个入口的用途、核验结果、授权缺口和接入所需字段见[官方气象与水利数据源](25_官方气象与水利数据源.md)。网页入口只用于人工核验；不得抓取前端页面并将其包装成稳定API。

## 数据单位与时间

- 所有界面时间按北京时间展示；内部保留Unix时间戳和带时区ISO时间。
- Open-Meteo当前降水按接口返回的 `interval` 展示。本次实际为900秒，即15分钟时段；不能当作1小时、3小时或24小时累计量。
- 当前值来自模型。中国区域15分钟值可能由小时模型插值。当前有效时刻不等于模型起报时刻，本接口未提供起报时间，故保留 `model_run_time: null`。
- 逐小时降水为对应时间戳之前1小时的累计量，页面显示起止时间窗。第一行可能是包含当前时刻的小时窗，并非全部尚未发生。风速是窗末时刻的模型值，不是该窗平均风速。
- METAR风速从原始报文的MPS或KT字段读取，KT按1852/3600转为米/秒；不以天气现象代码反推雨量。
- 缺失值保持 `null` 并显示“未提供”，不会补为0；空的天气现象代码也不用于判断是否安全。

## 刷新、缓存与故障

开启自动刷新且气象页面在前台时，每60秒请求本机API。服务器为每路数据保留600秒请求间隔；手动刷新也遵守该间隔。两路独立并行请求，单路失败不妨碍另一来源展示。关闭页面后不会在后台持续采集；再次打开会检查是否需要更新。

数据状态采用本项目的演示策略，并非官方时效标准：

| 状态 | 判定 | 界面与演练行为 |
| --- | --- | --- |
| 在时效内 | 模型有效时刻距本机时间不超过60分钟；机场观测不超过120分钟；最近请求成功 | 可以导入来源快照 |
| 已过期 | 超过上述阈值 | 保留时间和旧值供回看，不能作为新的演练参考 |
| 获取失败，有缓存 | 最近请求失败但有旧值 | 明确标记缓存和错误，不作为新的演练参考 |
| 暂无数据 | 无可用响应 | 显示缺失，不填模拟数值 |
| 时间异常 | 数据时刻超前本机时间5分钟以上 | 标记异常，禁止导入 |

机器系统时间需要正确。请求成功只能说明取得了数据，不能保证上游已经发布最新报文；以观测/有效时刻分别判断。上游有发布延迟，服务也可能暂不可用。

## 如何接到行动清单

1. 点击“载入快照到气象资料”。后端保存本次有效来源的不可变凭据。
2. 预警级别固定为“未说明”，灾种初始为空。由使用者手动选择暴雨或大风演练情景。
3. 核对场地与预案，勾选范围确认，生成规则演练清单。当前没有AI密钥，因此该结果明确标记未调用AI。
4. 导出JSON含完整输入快照、每路数据和时间；Markdown同时列出来源摘要。新近数据不会自动触发对外警报、发布或通行结论。
5. 后端拒绝修改过或过期的实时凭据。仅灾种可由使用者选择。快照凭据只保存在产生它的本机，新机器应重新获取，不应直接把旧凭据当作最新资料。

实时数据只提供气象背景。6个点位和5条预案仍为虚构/草稿，不能把演练任务数量解释为真实受灾点数。

## 接入与部署

代码仅依赖Python标准库，运行方式与原版相同：`python server.py`。默认监听127.0.0.1:8765，需要能够访问 `api.open-meteo.com` 与 `aviationweather.gov` 的网络环境。程序使用正常HTTPS证书校验，未关闭TLS校验。

主要文件：`live_data.py`负责获取、字段校验和时效；`server.py`提供本机API并保存快照；`web/`展示与导出；`tests/test_live_data.py`验证边界与缓存故障。GET `/api/live` 返回聚合快照。POST `/api/live/reference` 与 `/api/generate` 保留原有本机令牌校验。

Open-Meteo保留署名 `Weather data by Open-Meteo.com · CC BY 4.0`。当前使用无密钥免费接口开展非商业原型验证。免费托管API服务限定非商业用途；后续收费产品应按[服务条款](https://open-meteo.com/en/terms)评估商业接入。数据许可和托管API使用条件应分别核对。
