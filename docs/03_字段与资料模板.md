# 字段规范与资料填写模板

> 版本说明：本文保留第1—4天的阶段记录。2026-10-02已增加两路公开最新气象接入；最新能力、数据边界与验收见[实时接入说明](08_实时数据接入说明.md)。CMA账户接口、官方预警、真实AI与现场试点仍未完成。

## 1. 数据包结构

版本：1.0。原型直接导入JSON；以 `data/demo.json` 为可运行参考。所有时间必须带时区；界面按北京时间编辑。真实场地信息尚未提供，示范资料不得直接去掉“虚构”标记当作真实数据。

| 对象 | 字段 | 说明 |
|---|---|---|
| site | name / region / status / note | 场地名、城市、simulated或verified、说明 |
| weather | id / title / publisher / source_url | 资料编号、标题、机构、可核验HTTP(S)链接 |
| weather | published_at / replay_at | 发布时间、回放时间；禁止前者晚于后者 |
| weather | region / hazards / level | 城市、rain或wind数组、资料记录级别 |
| weather | mode / text_kind / text / scope_note | historical或simulation、原文/摘要性质、内容、适用范围限制 |
| points | id / name / type / region | 唯一编号、点位名、类型、城市 |
| points | features / source / status | 特征数组、来源、simulated或verified |
| plans | id / title / hazards / point_types | 条目编号、标题、适用灾种与点位类型数组 |
| plans | action / role / source / status | 任务原文、责任角色、条目出处、draft或verified |

点位类型参考：underground（地下入口）、low_path（低洼通道）、entrance（建筑入口）、outdoor（室外设施）、communication（信息汇总）。可增加类型，但必须与对应条目的point_types完全一致。

`verified`是资料提供者的核验标记，不代表系统独立认证或行政授权。填写前记录审核人角色、日期和允许用途；不要把个人联系方式填入演示包。

## 5. 字段检查与界面限制

- 点位与条目编号不得重复，记录各为1—30条。
- 点位城市、气象资料城市、场地城市必须一致才进入候选匹配；城市一致仍需人工核对具体街镇范围。
- 第4天版本不从自然语言自动推定灾种，需由用户勾选并与资料核对。
- 第4天版本不处理实时模式、不发布公众通知、不确认已积水、不计算概率或水深。
- 来源链接只用于用户回查，程序不会自动访问任意导入链接。
- 原型每次导出JSON包含完整输入快照，便于复现；分享前检查授权与脱敏。

## 6. 输出记录

输出包含run_id、生成方式、时间、耗时、输入快照、卡片与限制。卡片包括点位编号、条目编号、来源、建议责任角色、任务和待核验状态。`publishable`固定为false，不存在“生成即发布”。
